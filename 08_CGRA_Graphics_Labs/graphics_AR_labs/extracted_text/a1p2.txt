B.1 Timer Tool
The Timer Tool provides a memory-mapped timing device that can generate
timer interrupts.

While the tool is connected to the program, it maintains a clock starting
from time zero. The current time, in milliseconds, is available as a 64-bit
value at:
• 0xFFFF0018 – lower 32 bits;
• 0xFFFF001C – upper 32 bits.
The timer interrupt is conﬁgured by writing a 64-bit value, called timecmp,
to:
• 0xFFFF0020 – lower 32 bits;
• 0xFFFF0024 – upper 32 bits.
An interrupt is generated when the current time becomes greater than
or equal to timecmp.
For this assignment, unless necessary, you may use only the lower 32
bits of the timer.
The timer generates an interrupt only once for each conﬁgured value of
timecmp. Therefore, the timer must be rearmed by writing a new value to
timecmp from the timer interrupt handler.
Before interrupts can be generated, the interrupt handler address must
be placed in the utvec CSR and the appropriate bits of uie and ustatus
must be enabled.
For example, a timer interval may be deﬁned as:

timeLow : . word 0xFFFF0018
timeCompLow : . word 0xFFFF0020
.e q v milisecs 2 0 0
The timer can then be rearmed by reading the current time and adding
the desired interval.
B.2 Digital Lab Sim
The Digital Lab Sim provides two seven-segment displays. Only these dis-
plays are required in this assignment.
The displays are mapped as follows:
• byte at address 0xFFFF0010: right seven-segment display;
• byte at address 0xFFFF0011: left seven-segment display.

Each bit of the corresponding byte controls one segment of the display.
The displays will be used to provide information about the execution of
the surface-generation program.
B.3 Interrupt Handling
The interrupt mechanism introduced in this part must be compatible with
the surface-generation code developed in Part 1.
The interrupt service routine must determine the source of each inter-
rupt and dispatch execution to the appropriate handler.
The possible sources are:
1. a keyboard interrupt;
2. a timer interrupt;
3. another interrupt source, if applicable.
The common interrupt entry code must preserve the necessary proces-
sor state, identify the interrupt source, execute the corresponding handler,
acknowledge or rearm the device when necessary, and ﬁnally return to the
interrupted program.
Exercise B.1
Write the interrupt service routine entry code.
The ISR must identify whether the interrupt was generated by the key-
board or by the timer and dispatch execution to the corresponding handler.
The interrupt handler must preserve the processor state required to
return safely to the surface-generation code.
After the appropriate processing has been completed, the ISR must
return to the interrupted program.

For initial debugging, you may echo the received character on the text

B.4 Interactive Surface Generation
The surface-generation algorithm developed in Part 1 visits the pixels of
the Bitmap Display and calls surfacepixval followed by putpixel for
each pixel.
In this part, the generated image must remain the same mathematical
surface:
z = sin(x)c o s (y).
However, the program must now keep track of its progress while the
image is being generated.
A pixel counter must be maintained and incremented whenever a pixel
is written to the Bitmap Display.

B.5 Restarting the Surface Generation
The program developed in Part 1 generates the complete image by visiting
all pixels of the Bitmap Display.
In this part, the program must continue operating after a complete
image has been generated.

B.7 Testing
The implementation should be tested incrementally.
First, verify that the program from Part 1 still generates the correct
mathematical surface without interrupts.
Next, enable the Keyboard and Display MMIO Simulator and verify
that a keyboard interrupt is correctly detected and handled.
===== PAGE 7 =====
Then enable the Timer Tool and verify that timer interrupts are gener-
ated periodically and that the timer is correctly rearmed.
The seven-segment displays should then be tested independently.
Finally, combine the interrupt processing with the complete surface-
generation program.
During this ﬁnal test, verify that:
1. the mathematical surface continues to be generated correctly;
2. keyboard interrupts are handled while the surface is being generated;
3. timer interrupts occur periodically;
4. the pixel counter is updated whenever a pixel is generated;
5. the counter is reset after each timer interrupt;
6. the seven-segment displays are updated correctly;
7. the surface generation restarts after a complete image;
8. the program does not restart the surface from the beginning as a
consequence of an interrupt.
